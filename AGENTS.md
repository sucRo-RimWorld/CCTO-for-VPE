## Ownership
- This repo is the **single owner of cold-tolerance compatibility for the VPE plant ecosystem**, including related VPE plant add-ons. Do not create one CCTO patch Mod per VPE add-on. Keep one lightweight optional addon with conditionally loaded, separately organized XML for each separately installed provider. CCTO retains its C# framework and **all Vanilla/MO data**. MO separation is cancelled.
- **Source-implemented VPE 1.6 core scope:** 20 DefNames (original 14 ordinary plus six separately source-audited custom classes), all explicitly listed in `Docs/PlantBalance.json`; zero excluded. Preserve actual six original VPE `thingClass` identities, hardcoded traits and original fourteen numeric settings. This is source implementation only, not evidence of loaded-game PASS. Future related VPE add-ons are centrally owned here but **not yet implemented**. Track provider/repository/version and eligible vs custom Defs in `Docs/AddonInventory.json` and `Docs/AddonCompatibility.md`; do not silently expand supported plant lists or advertise candidate providers as supported.
- Do not change VPE or add-ons' plant classes, yield, fertility, harvest, recipes, graphics or growth days. Do not bundle other mods' assets or assemblies. Future addon patches must be **conditional on the installed provider**; no hard dependencies on optional child packs in About.xml, no XPath failures or unintended patches when absent, and no guessed top-level packageId. Keep pack-specific data/XML and tests separate from the existing base VPE 20-plant inventory and nine source-parity counterpart tests.
- `Docs/PlantBalance.json` is the reviewed implementation balance source; [TemperatureEvidence](Docs/Research/TemperatureEvidence.md) documents the botany-to-gameplay abstraction and [ImplementationDecision](Docs/Research/ImplementationDecision.json) owns the hashed VE/non-VE decision record. Never silently tune compiled XML instead of the balance source. All changes require source evidence, regeneration and static checks; native loaded-game behavior remains **unverified** unless directly evidenced; user bug reports are the adopted post-distribution validation route, not a substitute for evidence of a runtime PASS.
- The author does not use VPE and has explicitly waived mandatory pre-publication native RimWorld testing **for this optional addon only**. Require the owner static checks and packaging/public copy gates; disclose that native gameplay is unverified and handle reproducible player reports through issue #4. If an actual native test is later needed, use the shared persistent host; never bootstrap a chat-local game install or infer PASS from no reports.

## Integration and reports
- **SteamCMD Workshop updates are a separately author-approved operation for the existing public item `3819497323` only.** Source-audited `preflight` is nonpublishing; the protected manual `update_existing` workflow must validate the pinned source/host ID and Steam's current public (`visibility=0`) identity before and after upload. The SteamCMD VDF deliberately omits `visibility`; no first-item creation, privacy changes, arbitrary ID, automatic dispatch, or Steam credentials in GitHub. A mismatched host state is a hard HOLD and must not be overwritten. Historical private-only steps are superseded for this retained public item. Do not confuse CI or SteamCMD success with verified downloaded subscriber contents or authenticated creator identity. Owner runbook: `Docs/SteamCMDPrivatePublishing.md`.
- Changes use topic branches and PRs, never direct `main` edits. Keep `Docs/Coordination.md` authoritative on `main` only (PR integration may temporarily contain its pending change). Confirm exact PR checks before merge.
- Present **test premises and items** (20 included, six custom-class identities, nine existing CCTO analogues, exact dependency IDs, field behavior, no duplicate extension, no code assembly), their results and remaining untested scenarios.
- Steam release and Workshop publication are author-controlled; never claim either from CI or a repository merge.
